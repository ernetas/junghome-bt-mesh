# JUNG HOME device settings — UI inventory vs. our implementation

Goal: every device setting the JUNG HOME Android app (v2.2.0) exposes in its UI, per device type, the mesh
message/property behind it, and what `custom_components/junghome_ble` (`jhmesh/` + HA platforms) already
covers — so the devices can later be configured from Home Assistant without the app ("no provisioning,
just change what the UI can change").

Builds on (read those first, they are not repeated here):

* `docs/android/properties.md` — property catalogue, value encodings, enums (cited as **props §x.y**)
* `docs/android/vendor-models.md` — vendor opcodes / framing (**vm §x.y**)
* `docs/android/network-logic.md` — control paths §4, status §5, connections §2, scheduler §6.3 (**nl §x.y**)

Source paths below are relative to `android/jadx-out/sources/`. Abbreviations:
`PROV/` = `de/jung/junghome/app/ui/configuration/deviceParameter/providers/`,
`UI/` = `de/jung/junghome/app/ui/`, `DOM/` = `de/jung/junghome/domain/`, `RES/` = `de/jung/junghome/data/mesh/resolver/`.
UI labels are the English `res/values/strings.xml` values. Where the default jadx output failed to decompile a
method, line numbers marked **(simple)** refer to the same class decompiled with
`jadx --decompilation-mode simple --show-bad-code --no-imports --no-res` (the mode also used in `network-logic.md`;
`--no-inline-anonymous --no-inline-methods --single-class` for `UI/configuration/deviceInfo/c.java`).

**Status legend** — `done`: implemented in `jhmesh` *and* exposed in HA; `lib`: a builder/decoder exists in
`jhmesh` (today only the generic vendor-property *Get* `messages.vendor_property_get()` and `describe()`, which
prints raw value bytes — no per-property decoder, no vendor *Set*) but no HA entity; `todo`: nothing.
"HA" column = suggested representation (`number`/`select`/`switch`/`button`/`sensor`/`text` entity,
`EntityCategory.CONFIG` unless stated, or a config-entry option).

## 1. How the app's settings screens are built (common plumbing)

### 1.1 Screens

Every device has a "Configuration" activity with three tabs: **Display** (device page = live control plus
device-specific setup), **Parameters** and **Info** (`strings.xml configuration_tab_display_title`,
`configuration_tab_parameter_title`, `configuration_tab_info_title`). The Parameters tab is generated by a
*parameter provider* chosen per device class — the first provider whose `a(device)` matches
(`UI/configuration/deviceParameter/NewDeviceParameterViewModel$deviceFlow$1.java:59-76`); `d()` returns the
normal list, `b()` the **expert** list shown after the "Activate expert mode?" dialog
(`strings.xml expert_mode_parameter_*`).

### 1.2 Read / write flow (identical for every parameter)

* **On screen open** every cell requests its capability once per capability class:
  `C1866w.a()` → `CommunicateWithDevice(deviceId, capability, REQUEST, waitForStatus=true)`
  (`PROV/C1866w.java:37-43`). For vendor properties that is an acknowledged **LBC Admin/Manufacturer/User
  Property Get** to the element address baked into the capability (vm §3.3, nl §4.1); for SIG capabilities the
  corresponding SIG Get.
* **On change**: `C1866w.b()` → `CommunicateWithDevice(…, UPDATE, waitForStatus=true)` (`PROV/C1866w.java:45-58`)
  = acknowledged Set, 3 attempts × 3 s (nl §5.1); the reply (or the `D1 27 05` user-status fallback, vm §5) updates
  the cell. No follow-up read except where noted (blind reference run, §7).
* Some cells are disabled with an info line when the firmware is too old (`PROV/C1863t.java:9-22`):
  automatic DST needs SW ≥ 1.1.0.0 (`Y7/q0.java:1342-1347`), touch sensitivity ≥ 1.0.3.3, sensor values for IoT
  ≥ 1.3.0.0 (`de/jung/junghome/data/cloud/api/a.java:45-57`), RTR HVAC mode ≥ 2.2.0.0 (props §3.3).
* **Element addressing**: node-level properties go to the element that hosts the LBC Admin Property Server —
  the primary element for push-buttons/sockets/RTR (props §3.1); for **detectors** the sensor properties go to the
  admin server of the **highest** element and only 0x0001 DeviceKeyLock to the first one
  (`p012a8/a.java:1536-1554` vs `:1588-1600`, capability construction `:2262-2360`); per-key properties go to the
  key element; LED properties to the first admin-server element (`Z7/a.java:294-300`).

### 1.3 Corrections to `properties.md` found while doing this

1. **`SchedulerEnabledProperty` is `0x1246` (4678)**, not `0x1236` (`p056e8/r.java:2340`); `vendor-models.md` §3.6
   and `network-logic.md` §4.2 already say 4678/0x1246. `DropOfTempStateProperty` is `0x1212` (4626), not `0x121A`
   (`p056e8/r.java:2040`).
2. **LED mode byte (0xA0xx, last byte)**: `5` means **night mode ON**, `0` night mode OFF — the UI toggle "Night
   mode" rewrites *every* LedModeOn/LedModeOff capability of the device with `f = nightMode`
   (`p036ca/a.java:196-210`, encoder `C6/a.java:190-209` + `A8/b.java:8-11`, decoder `RES/C1901b0.java:96-131`).
   `properties.md` §1.8 calls it "LED enabled"; the colour and "enabled" are independent (NoColor = 0,0,0).
3. The 0x0001 encoder really is MSB-first-then-byte-reversed: `new k0(16)` selects the Nordic-style writer
   (`androidx/compose/animation/core/k0.java:176-179` → case 4, `:97-128`), so the wire layout is a LE u16 with
   bit0 = local-factory-reset lock, bit1 = factory-reset-with-time-limit, bit2 = local devices lock, bit3 = key
   lock, bit4 = configuration lock (`J8/C0541i.java:72-85`, field names `V7/C0849f.java:64-73`). The mirrored
   decoder (props §5 open question 1) still needs a field test.

## 13. Open questions

1. **0x0001 bit order** — encoder vs. decoder disagree in the app (§1.3.3, props §5 q.1). Read the word from a
   socket/rocker with all locks off, toggle "Lock operation" in the app, read again.
2. **Blind 0x1102** — the app writes the 2-byte seconds form; `MoveUpDownTimeProperty` (4-byte ms) shares the ID
   (props §5 q.2). Confirm the status length on a real blind before exposing the `number`.
3. ~~**Ack of parameter Sets**~~ **settled on air** (`0148`, sniffer recording, `hidden-features.md`
   §9): an LBC **Admin Property Set (acked) is answered with a unicast Admin Property Status in ~0.25 s**, whether
   the value changed or not, and **nothing is published** to the element group; **Admin Property Set Unack (`C4`)**
   is applied silently (read-back confirms) — so the acked-Set-then-read-back strategy of `config_entities.py`
   is right and the read-back is only a fallback. Side effect to know: the Set's access byte *is written* — a
   property whose userAccess read `1` reads `3` after our Set with access 3, exactly as after the app's Sets.
   SIG setup Sets behave per spec except two: OnPowerUp Set, Lightness Default Set and CTL Default Set answer
   unicast; **Light Lightness Range Set** answers only with the *publication* of its status to the element group
   (twice, like OnOff), and **Light CTL Temperature Range Set** is not answered at all (nothing unicast, nothing
   published) — the DALI insert's range is not settable this way.
4. **DimMode userAccess = 1** — unknown whether access 3 would be rejected; replicate the app.
5. **Units not visible in code** — 0x6004/0x600F assumed lux (slider says lx), 0x6021 u8 unit unknown (props §5 q.5).
6. **Detector element addressing** — the app sends sensor properties to the highest element and 0x0001 to the
   first (§1.2); confirm with a Get to both elements on a real detector.
7. **Second channel and 0x000F/0x0001** — these are node-level (primary element) properties; for 2-channel devices
   HA should expose them once per node, not per channel.
8. **CTL Default deltaUV** — the app echoes the last read deltaUV (`capability2.N()`); if no CTL Default status was
   received it throws. Use 0.
9. **Battery transmitters** — every config message must be preceded by a key press (`control_switch_sleep_mode_*`);
   how long the node stays awake and whether the 6 s keep-alive is needed for a single Set is untested.
10. The app's unused strings (`device_parameter_hotel_*`, `night_light_*`, `maximum_floor_temperature_*`,
    `presence_simulation`, `operation_lock_*`, `rtr_heating_option_*`, `wind_alarm`, `temperature_measurement_*`)
    hint at firmware features without an app UI (`de/jung/junghome/R.java` only); their properties (e.g. 0x1208,
    0x6007) are declared but never written — leave alone.
